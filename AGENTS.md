# AGENTS.md: rules for AI agents and new maintainers

You maintain **Deadlock Server Picker**, an open-source tool that blocks Valve Steam Datagram Relay (SDR) PoPs with OS firewall rules, so Deadlock (app 1422450) matchmaking avoids unwanted regions. These rules are binding.

## Hard constraints

- **No GitHub Actions.** Actions is disabled for billing reasons.
  - The merge gate is the `local-ci` commit status posted by `scripts/ci` from the maintainer's machine.
  - `.github/workflows/ci.yml` is a mirror for `act` only. Never depend on it.
  - No Dependabot and no CodeQL default setup.
- **Never:**
  - force-push or rewrite `main`
  - delete published tags or releases
  - commit secrets or tokens (get the token from `gh auth token` at runtime)
  - change the repo's visibility
  - merge with a red or missing `local-ci`
- **No code path may touch firewall entries outside our namespace.** The namespace is:
  - Windows: rules whose Name matches `DeadlockServerPicker_<pop>_(in|out)`, in group `DeadlockServerPicker`
  - nftables: table `inet dsp_deadlock_server_picker`
  - iptables: chain `DSP_DEADLOCK_SERVER_PICKER` and the jumps to it from `OUTPUT` and `INPUT`
- `reset` must leave zero traces. Never use global resets (`netsh advfirewall reset`, `iptables -F` without a chain, `nft flush ruleset`).
- **Non-goals:** modifying game files, memory or launch options; VPN or routing tricks; anything that could be considered cheating. The `citadel_region_override` console command may only be *shown* as a tip.

## Workflow

1. Work only from GitHub issues, and keep every issue's acceptance criteria up to date. The pinned **Roadmap** issue tracks phases and milestones.
2. One branch per issue: `<type>/<issue>-<slug>`.
3. Conventional Commits. The PR title becomes the squash commit and the changelog entry.
4. Keep PRs small and put `Closes #N` in the description. Use the PR template checklist.
5. Push, open the PR, then run `scripts/ci`. It posts `local-ci` on the PR head and appends the CI summary to the PR description. It refuses to post when the tree is dirty or HEAD isn't the pushed PR head.
6. For firewall changes, add the `--dry-run` output to the PR description.
7. Once `local-ci` is green, merge with `gh pr merge --squash --delete-branch`.
8. If you can't verify something yourself (in-game behaviour, or a real firewall on an OS you're not running), open an issue labelled `needs-manual-test` with a step-by-step checklist. Releases stay **pre-release** until the maintainer completes the in-game checklist.

## Definition of done (every PR)

- Tests added or updated, `just ci` green, and `local-ci` posted.
- Docs updated if the change is user-facing. The CHANGELOG is generated by git-cliff at release time from PR titles.
- No firewall entries touched outside our namespace, and `reset` verified to leave zero traces.

## Commands

| Command | Purpose |
|---|---|
| `just hooks` | install the git hooks (pre-commit: fmt-check + lint; pre-push: quick tests) |
| `just ci` | fmt-check, lint, test, build win-x64 + linux-x64, license audit, vulnerability scan |
| `scripts/ci` | run `just ci` and post the `local-ci` status (PR branches only) |
| `just integration-linux` | real nftables/iptables tests in a throwaway network namespace (WSL or Linux, root) |
| `scripts/check-sdr-drift` | compare the live SDR config with the fixtures and open an `sdr-drift` issue |
| `scripts/release vX.Y.Z` | tag, build, checksum and publish a GitHub release (pre-release by default) |

On Windows, run `just` and the scripts from **Git Bash**. In PowerShell, `bash` launches WSL.

## Architecture

- `src/DeadlockServerPicker.Core`: SDR config fetch, cache and parse; region mapping (`regions.json`, embedded); ping; planner (desired vs current diff); firewall backends; command runner; logging; elevation checks.
  - Backends **only generate commands**. Execution goes through `ICommandRunner`, so tests assert exact commands with golden files.
- `src/DeadlockServerPicker.Cli`: the `dsp` CLI. Hand-rolled argument parsing; `--json` on every command, `--dry-run` on mutations.
- `src/DeadlockServerPicker.Gui`: the Avalonia 12 GUI, code-only (no XAML).
- `tests/DeadlockServerPicker.Tests`: xUnit v3 on Microsoft.Testing.Platform. Fixtures are real API snapshots; golden files live in `golden/`.
- Decisions are recorded in `docs/adr/`. Read them before changing the stack, the firewall mechanism or elevation.

## Style

- Keep it simple: no interfaces with a single implementation unless a test needs the seam (`ICommandRunner`, `IPinger`, `IFirewallBackend` are justified).
- Firewall and network work stays off the UI thread.
- Never parse localized command output. On Windows, read JSON from PowerShell.
- Error messages say what happened and what to do next.
